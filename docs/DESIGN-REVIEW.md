# 设计与实现审查

2026-10-17，审查版本 0.2.1，修复版本 0.2.2。覆盖命令入口、配置、CLI 环境、Chrome/Desktop 启动、代理转发、后台服务、安装脚本与现有测试。

## 结论

项目的主流程已经连通：配置 → 检查 → 启动官方客户端 → 经固定上游转发；服务启停、故障阻断和 Desktop 按字段恢复也有实现。代码规模较小，按职责分文件、直接调用标准库，未发现需要引入新框架或接口层的问题。

完备性主要受外部客户端与配置边界影响。单元/集成测试能验证 ccg 的行为，不能证明 Desktop、未来版本 Claude Code 或独立工具的所有实际连接都受代理约束。

## 本次修复

| 发现 | 修改与影响 |
| --- | --- |
| `listen` 只排除字面值 `0`，空端口、服务名、超范围端口等仍能通过校验；上游端口也缺少范围检查 | 统一校验十进制 1–65535 端口，在启动前拒绝无效配置；代理目标复用同一校验 |
| 自代理检查直接比较端口字符串，遗漏 HTTP/HTTPS 默认端口、前导零及大小写 localhost | 按协议补齐默认端口，使用数值比较，并归一化 localhost，提前拒绝这些自代理环路 |
| 地区代码只检查长度和大小写，`12`、`S1` 也被接受 | 配置与 trace 解析共享两个大写 ASCII 字母的校验 |
| JSON 解码只读第一段，文件末尾的第二个对象或垃圾内容被忽略 | 要求解码后到达 EOF，继续允许空白，保留未知字段检查 |
| CLI 设置检查一路扫描父目录，将祖先 HOME 的默认 `~/.claude/settings.json` 再次当作项目设置；其中的 `apiKeyHelper` 会误阻止独立 CLI | 在到达祖先 HOME 时停止扫描；明确选择的用户配置仍单独检查，Desktop 默认设置与项目冲突检查保留 |
| HTTP 转发仅清理第一条 `Connection` 中声明的逐跳字段 | 遍历所有 `Connection` 头，双向清理，同时保留端到端字段 |
| 上游 HTTP 响应中途断流仍向下游正常结束，并记录为完成 | 中止下游响应并计入失败，使客户端能识别截断；客户端写入失败单独记录 |
| 控制请求固定 40 秒超时，小于配置允许的 120 秒探测超时 | 普通本地控制请求使用短超时，启动前 `/check` 使用探测超时加 5 秒余量 |
| 启动自动检查与并发 `/check` 排队执行相同探测，增加等待和重复连接 | 合并重叠请求：等待期间已有检查完成时直接复用该结果；后续独立检查仍会重新探测 |
| 测试配置依赖本机已安装的 Claude 和系统代理 | 测试固定模拟客户端路径与上游，不要求安装真实 Claude |

README 已重排为用途、快速开始、日常操作、网络、配置和边界；Desktop 细节移入 [独立说明](DESKTOP.md)。移除“当前机器”和旧客户端版本等不适合作为长期说明的措辞。

## 保留的设计与已有简化

- **本地代理层**：在上游代理前统一做健康检查和新请求阻断，不另做节点选择、TLS 解密或账号代理。若只需要设置 `HTTPS_PROXY`，这一层会显得多；对于常驻状态与故障阻断目标，它有明确职责。
- **完整备份与字段恢复记录**：备份用于人工恢复；字段记录让自动撤销保留用户后来添加的设置。整文件回滚会破坏这一行为。
- **CLI 与 Desktop 配置分开**：CLI 使用独立目录，Desktop 使用其自身登录与默认 Code 设置，不能为了复用代码混用身份目录。
- **按职责分文件**：目前不需要为 Desktop 再建管理器或通用工作流。少量启动参数相似，尚不足以引入公共抽象。

前一轮已完成的精简继续保留：共享 `startDetached`、网络配置单独计算服务摘要、重复 Desktop setup 不重写文件、PopCat 模板单一来源 embed，以及删除重复校验与无用字段。本次未增加外部依赖。

## 尚未覆盖的边界

| 项目 | 当前范围与后续条件 |
| --- | --- |
| Desktop 真实验收 | 配置恢复与启动参数有测试；官方应用的登录、界面、本地 Code、停止代理后的表现和时区仍需按 [验收步骤](DESKTOP.md#网络范围与验收) 实测 |
| 组织策略与动态项目 | 当前检查已知文件，不完整枚举 MDM、服务端或宿主下发的策略；Desktop 后来打开的项目也可能覆盖用户设置。需结合实际会话 `/status` 验证 |
| Desktop 写入事务 | 恢复记录与设置是两个文件，异常中断会保守地留下冲突；并发修改检查是写入前快照比较，不是跨进程事务锁。冲突后需人工核对记录与备份，尚无自动修复命令 |
| 自定义安装目录 | 安装脚本支持 `CCG_INSTALL_DIR`，自动卸载只支持 `~/.local/bin`；自定义安装仍需手动清理命令和辅助链接 |
| 状态命令用于自动化 | `auth status` 当前通过文字区分未登录/读取失败，退出码仍为 0；`status` 在服务未运行时也返回 0。脚本不能仅凭退出码判断就绪 |

这些限制已与“配置检测通过”区分，不将静态配置检查描述为端到端保证。
